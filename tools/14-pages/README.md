# 14-pages：上下文按 12 小时分页

会话一长，每轮都要把全部历史过一遍，回一个字也要好几秒。DSH 内核不给插件改历史的接口，所以换个做法：**把历史切成一页一页的文件，新会话只读最新那一页，往前找到才读旧页。**

## 生成

```bash
node tools/14-pages/page-archive.mjs     # 增量分页 + 刷新页索引
node tools/14-pages/compact-session.mjs  # 刷最近 12 小时的「接续」页
```

环境变量（都可省）：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `DSH_SHARED_DIR` | `~/.dsh/im` | 灵魂工作区，页写进 `shared/全量/页/` |
| `SOUL_SESSIONS` | `~/.dsh/sessions` | DSH 会话目录，`-archive` 会一起扫 |

## 产出

```
shared/接续.md                最近 12 小时，开新会话先读它
shared/全量/页/索引.md        所有页的目录：时段 / 条数 / 那会儿在说啥
shared/全量/页/2026-11-03-AM.md
shared/全量/页/2026-11-03-PM.md
```

## 读法（写进 AGENTS.md 的就是这套）

1. 先读 `shared/接续.md`。
2. 里面没提到的事，看 `shared/全量/页/索引.md`，从最新一页往前**一页一页**翻，一次只读一页。
3. 翻到能对上的就停，不用再往前。
4. 页里也没有，才去 `shared/全量/YYYY-MM-DD.md` 或向量回忆（`rag-recall`）。

## 定时

```bash
node tools/14-pages/pages-schedule.mjs
```

0 点 / 12 点各跑一次。起来的那一刻先看一眼上一班有没有跑：**错过了就立刻补跑**（关机、程序没开都算），所以不会漏消息 —— 补跑读的是会话文件本身，跟「上次跑到哪」无关。

状态记在 `~/.dsh/im/.pages-schedule.json`。

## 细节

- 增量：每条消息按 `时间+说话人+前 120 字` 算指纹，记在 `.state.json`，重复跑不会写重。
- 更快：会话文件没动过（mtime 没变）就整个跳过，不再解压，第二次跑几乎不花时间。
- 一天两页：00:00–12:00 记 `-AM`，12:00–24:00 记 `-PM`。
- 过滤掉系统提示、运行时上下文、附件清单这类噪声，只留「谁说了什么」。
- 接续页会合并最近 12 小时里的**多个会话**，换过窗口、新开过会话都不漏；总字数封顶约 8 千，更早的留在分页里。
- 会话文件是 zstd 帧拼接的，按帧魔数切开逐段解，不依赖 DSH 内部解码。
