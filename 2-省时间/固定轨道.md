# 轨道（概念）

> 这一页只讲机制，**不放任何具体轨道** —— 轨道是每个人自己攒的操作习惯，别人的配方对你没用。
> 新装上来的轨道列表是**空的**（`emptyDb()`），一条都不预置，自己攒。

## 是什么

把一条反复走的操作路线存成配方：**名字 + 关键词 + 分步 + 跑不通怎么退**。
下次遇到类似的事，先查轨道，照着走，别重新摸一遍。

## 怎么存

用 `soul` 工具的 `track-save`：

- `name`：短名，比如「出图」这种你自己认得的名
- `keywords`：逗号分隔的检索词
- `steps`：分步，用 ｜ 或换行分隔
- `fallback`：跑不通怎么退回

同名（不分大小写）再存会覆盖内容，原来的「用过几次 / 失败几次」保留。

数据落在 `<工作区>/shared/轨道.json`；文件不存在就按空表处理，第一次保存时才建文件；写盘走原子写。

## 怎么查

- `track-show` + `query`：按名字 / 关键词模糊匹配一条，回完整步骤和退路
- `track-list`：列全部轨道（名字 / 关键词 / 用过几次 / 失败几次）

匹配顺序：名字完全相同 > 名字互相包含 > 关键词命中。

## 跑完怎么记账

`track-bump` + `query` + `ok`：

- 跑通：`uses + 1`
- 没跑通：`uses + 1`，`fails + 1`

用得多、失败少的排在列表前面。记账是为了以后挑路线时知道哪条靠谱。

## 跑不通怎么退

- 每一步之间的退路写在 `fallback` 里：卡住就退到上一步重来，别硬往下钻
- 同一条路线连试两次不通，就换路或者问人，别在原地打转
- 轨道只是「上次是怎么做通的」，不是保证 —— 环境变了要重存
